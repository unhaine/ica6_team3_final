## D001. 프론트엔드 프레임워크 선택

| 항목       | 내용       |
| ---------- | ---------- |
| **날짜**   | 2026-01-26 |
| **상태**   | 승인       |
| **결정자** | 개발팀     |

### 배경

식재료 관리 앱은 이미지 업로드, 실시간 알림, 복잡한 상태 관리가 필요합니다.

### 결정

**Next.js 15 (App Router)** 사용

### 대안

| 대안              | 장점                                         | 단점           |
| ----------------- | -------------------------------------------- | -------------- |
| **Next.js 15** ✅ | SSR/SSG 지원, API Routes 내장, 이미지 최적화 | 러닝커브       |
| Vite + React      | 빠른 HMR, 가벼움                             | 별도 서버 필요 |
| Remix             | 중첩 라우팅 좋음                             | 생태계 작음    |

### 이유

- API Routes로 백엔드 별도 구축 불필요
- 서버 컴포넌트로 성능 최적화
- Vercel 배포 최적화

## D002. 데이터베이스 선택

| 항목     | 내용       |
| -------- | ---------- |
| **날짜** | 2026-01-26 |
| **상태** | 승인       |

### 배경

사용자-식재료-레시피 간 관계형 데이터 저장 필요

### 결정

**PostgreSQL + Prisma ORM**

### 대안

| 대안              | 장점                       | 단점             |
| ----------------- | -------------------------- | ---------------- |
| **PostgreSQL** ✅ | 관계형, JSONB 지원, 안정적 | 설정 복잡        |
| MongoDB           | 스키마 유연                | 관계 처리 어려움 |
| Supabase          | 빠른 시작, 인증 내장       | 커스텀 제한      |

### 이유

- 식재료-마스터 데이터 관계 처리 용이
- JSONB로 레시피 재료/조리법 저장
- Prisma로 타입 안전성 확보

## D003. AI 이미지 분석 API 선택

| 항목     | 내용       |
| -------- | ---------- |
| **날짜** | 2026-01-26 |
| **상태** | 승인       |

### 결정

**Google Vision API** (이미지 인식) + **Gemini 1.5 Pro** (LLM)

### 대안

| 대안                          | 장점                         | 단점         |
| ----------------------------- | ---------------------------- | ------------ |
| **Google Vision + Gemini** ✅ | OCR 성능 우수, LLM 연동 용이 | 비용         |
| OpenAI GPT-4 Vision           | 통합 솔루션, 정확도 높음     | 비용 더 높음 |
| Naver Clova                   | 한국 특화                    | 범용성 낮음  |

### 이유

- Google Vision API로 영수증 OCR + 냉장고 물체 인식
- Gemini 1.5 Pro로 레시피 추천 및 AI 싱크로율 판단
- 사용자 교정 데이터로 정확도 99% 목표
