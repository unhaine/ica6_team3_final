## D001. Google Vision API 선택

| 항목       | 내용       |
| ---------- | ---------- |
| **날짜**   | 2026-01-23 |
| **상태**   | 승인       |
| **결정자** | -          |

### 배경

냉장고 내 식료품을 자동으로 인식하기 위해 객체 탐지 API가 필요합니다.

### 결정

Google Vision API의 Object Localization 기능을 사용합니다.

### 대안

| 대안              | 장점                             | 단점                           |
| ----------------- | -------------------------------- | ------------------------------ |
| Google Vision API | 높은 정확도, 간편한 연동, 문서화 | 유료 (월 1000건 무료)          |
| AWS Rekognition   | AWS 생태계 통합                  | 설정 복잡, 식료품 특화 아님    |
| 자체 YOLO 모델    | 커스터마이징, 비용 절감          | 학습 필요, 초기 개발 시간 증가 |
| Clarifai          | 식품 인식 모델 제공              | API 응답 형식 변환 필요        |

### 이유

- MVP 단계에서 빠른 개발 필요
- 높은 인식 정확도 보장
- Object Localization으로 Bounding Box 좌표 직접 제공
- 월 1000건 무료 티어 활용 가능

### 결과

- Google Cloud 계정 및 Vision API 키 필요
- 향후 트래픽 증가 시 자체 모델로 전환 고려

### 참고

- [Google Vision API 문서](https://cloud.google.com/vision/docs/object-localizer)
- [요금 정책](https://cloud.google.com/vision/pricing)

## D002. Canvas vs SVG 렌더링

| 항목       | 내용       |
| ---------- | ---------- |
| **날짜**   | 2026-01-23 |
| **상태**   | 제안       |
| **결정자** | -          |

### 배경

Bounding Box를 이미지 위에 오버레이하고 드래그 인터랙션을 구현해야 합니다.

### 결정

Canvas (Fabric.js 또는 Konva.js) 사용을 제안합니다.

### 대안

| 대안                  | 장점                       | 단점                     |
| --------------------- | -------------------------- | ------------------------ |
| Canvas (Fabric.js)    | 강력한 인터랙션, 성능 우수 | 러닝 커브, 접근성 제한   |
| Canvas (Konva.js)     | React 친화적, 레이어 지원  | 라이브러리 크기          |
| SVG (직접 구현)       | 접근성, DOM 조작 용이      | 복잡한 드래그 구현       |
| SVG (react-draggable) | 간단한 드래그              | 크기 조절 구현 추가 필요 |

### 이유

- 드래그 + 리사이즈 인터랙션 기본 제공
- 이미지 위 레이어 관리 용이
- 다수의 박스 렌더링 시 성능 유리

## D003. 데이터베이스 선택

| 항목       | 내용       |
| ---------- | ---------- |
| **날짜**   | 2026-01-23 |
| **상태**   | 승인       |
| **결정자** | -          |

### 배경

식료품 목록과 스캔 기록을 저장할 데이터베이스가 필요합니다.

### 결정

Supabase (PostgreSQL) 사용

### 대안

| 대안           | 장점                         | 단점                     |
| -------------- | ---------------------------- | ------------------------ |
| Supabase       | 무료 티어, 실시간, Auth 내장 | Vendor lock-in           |
| Firebase       | 실시간 동기화, 간편한 설정   | NoSQL 스키마 관리 어려움 |
| PlanetScale    | MySQL 호환, 브랜칭           | 무료 티어 제한적         |
| SQLite (local) | 서버 불필요, 간단            | 다중 기기 동기화 불가    |

### 이유

- PostgreSQL 기반으로 관계형 데이터 관리 용이
- 내장 Auth로 사용자 인증 간편
- 무료 티어로 MVP 충분
- Real-time 구독으로 향후 확장 가능

### 결과

- Supabase 프로젝트 생성 필요
- Storage 기능으로 이미지 저장도 통합

### 참고

- [Supabase](https://supabase.com)

## D004. 프레임워크 선택 (Next.js)

| 항목       | 내용       |
| ---------- | ---------- |
| **날짜**   | 2026-01-23 |
| **상태**   | 승인       |
| **결정자** | -          |

### 배경

웹 애플리케이션 프레임워크 선택이 필요합니다.

### 결정

Next.js (App Router) 사용

### 대안

| 대안         | 장점                         | 단점                      |
| ------------ | ---------------------------- | ------------------------- |
| Next.js      | SSR, API Routes, Vercel 배포 | 러닝 커브                 |
| Vite + React | 빠른 빌드, 단순함            | SSR 미지원, API 별도 구축 |
| Remix        | 풀스택, 데이터 로딩          | 생태계 작음               |

### 이유

- API Routes로 백엔드 통합 (Vision API 호출)
- Vercel에 최적화된 배포
- 이미지 최적화 내장 (next/image)

### 결과

- Next.js 14+ App Router 사용
- Vercel 배포 예정
