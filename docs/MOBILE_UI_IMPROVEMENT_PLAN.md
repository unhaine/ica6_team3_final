# 모듈 통일 및 고도화 개선 계획 (Improvement Plan)

`AppHeader`와 `BottomNavBar` 간의 일관성을 확보하고, 검토된 이슈들을 해결하기 위한 3단계 개선 계획입니다.

---

## 🎯 목표: "패턴의 통일과 의존성 제거"

### 1단계: 패턴의 통일 (Structural Unification)

`AppHeader`에 적용된 컴포지션 패턴을 `BottomNavBar`에도 동일하게 적용하여 구조적 통일감을 제공합니다.

- **BottomNavBar 리팩토링**:
  - `BottomNavBar.Item`, `BottomNavBar.Fab` 서브 컴포넌트 도입.
  - 배지(Badge) 표시 기능을 서브 컴포넌트 수준에서 유연하게 추가할 수 있도록 구조 변경.
- **Convenience Wrapper 유지**:
  - 기존처럼 `items` 배열만 넘겨도 동작하는 간편 방식은 그대로 유지하여 하위 호환성 확보.

### 2단계: 안정성 및 퍼포먼스 강화 (Stability & DX)

훅 시스템의 고질적인 문제인 '상태 잔류'와 '불필요한 리렌더링'을 해결합니다.

- **상태 리셋 로직 도입**:
  - `useHeader`, `useBottomNav` 훅이 컴포넌트 `unmount` 시점에 상태를 자동으로 초기화하도록 수정 (안정적인 페이지 전환 보장).
- **얕은 비교(Shallow Compare) 최적화**:
  - Context 내부에서 `state` 값이 실제로 변했을 때만 업데이트되도록 방어 로직 추가.
- **자동 메모이제이션**:
  - 사용자가 `onBack` 등 함수를 넘길 때 가급적 안정적인 참조를 유지할 수 있도록 훅 내부 인터페이스 개선.

### 3단계: 의존성 분리 및 프로젝트 독립성 (Decoupling)

공통 모듈이 특정 라이브러리에 의존하지 않도록 의존성을 외부로 밀어냅니다.

- **Action Injection**:
  - `AppHeader` 내부의 `signOut`로직을 제거하고, `HeaderProvider` 초기화 시점에 `globalConfig`로 주입받거나 개별 훅에서 핸들러를 넘기도록 변경.
- **Navigation Bridge**:
  - `useRouter`를 직접 호출하지 않고, 외부에서 넘겨받은 `onBack` 핸들러가 없을 때만 동작하는 기본 동작을 프로젝트 레벨에서 정의.
